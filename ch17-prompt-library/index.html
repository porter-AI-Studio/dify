第 17 章 · Part 5：整合開發

Prompt Library 與知識管理

介紹基於 AUTOMAT 框架的高品質 Prompt 知識庫設計，包含 FastAPI/SQLite 搜尋後端、端點設計與 Dify 工作流節點配置。

一、AUTOMAT 框架與 Prompt 知識化

在企業落地 AI 應用時，員工最常遇到的障礙不是「不會用軟體」，而是「寫不出好 Prompt」。為了協助員工快速上手，我們需要建立一個集中式的 Prompt Library (提示詞知識庫)。

在此知識庫中，所有的 Prompt 都遵循業界公認結構化最完整的 AUTOMAT 框架 進行撰寫：

字母 代表含意 說明與實作範例
A Actor (角色) 定義 AI 扮演的專業身分（例如：資深 HR 顧問）。
U User (目標對象) 設定 Prompt 的服務對象或最終讀者（例如：新進員工）。
T Task (任務) 明確交付給模型的具體工作任務與範疇。
O Output (輸出格式) 規範回傳資料的格式（如 Markdown 表格、JSON 或是特定長度）。
M Method (方法) 指導模型推理或分析所使用的方法學（如 STAR 原則、自動評估框架）。
A Assumption (假設條件) 設定分析的前提假設或安全邊界（如「假設公司預算有限」）。
T Tone (語氣風格) 約束輸出的語氣風格（例如：客觀專業、溫柔同理）。

二、系統架構與資料表設計

為了讓用戶能用「自然語言」直接在聊天機器人中搜尋這 30+ 個高品質的 AUTOMAT Prompt，我們設計了以下前後端分離（Profile A）的整合架構：

資料表設計：PromptLibrary

我們在 SQLite 中建立了 PromptLibrary 表，除了基礎的 id、category（如 HR、Marketing、IT 等）、name、tags 之外，每一個 AUTOMAT 的核心元素都被拆分為獨立的資料庫欄位。這樣做的好處是，下游的 LLM 節點可以精準提取特定結構，而不需要用正則表達式去痛苦地切割整篇 Prompt 文字。

三、API 端點設計

FastAPI 後端提供了極簡的高性能查詢端點：

  • GET /prompts：列出所有的提示詞清單，支援使用 category 參數進行篩選。
  • GET /prompts/search?q={query}：關鍵字搜尋。後端會對 name、description 與 tags 欄位進行模糊檢索，返回評分與符合條件的 JSON 清單。
  • GET /prompts/{id}：獲取特定 ID 的 Prompt 的完整內容（包含 example Markdown 範例）。

四、Dify Workflow 整合節點

在 Dify 中，我們透過以下工作流（DSL 檔案名為 automat-prompt-library.yml）串接此 API：

  1. 意圖分析（LLM 節點）：從使用者的自然語言輸入中，識別其想要搜尋的類別或關鍵字。例如使用者輸入「我想寫一封行銷文案」，LLM 會輸出關鍵字 Marketing。
  2. 搜尋知識庫（HTTP Request 節點）：調用 FastAPI 搜尋端點： 
    GET http://localhost:8005/prompts/search?q={#intent_llm.text#}
  3. 範例展示與格式化（LLM 節點）：將 API 返回的 JSON 陣列，按照 AUTOMAT 各欄位漂亮地格式化為 Markdown 輸出給使用者。

五、本地開發與啟動

若要在本地開發或測試此 Prompt Library 服務，請於主機執行以下指令：

Powershell (本地端啟動) 
# 1. 建立與啟動虛擬環境
cd c:\VSCode_Proj\Dify\prompt-library
python -m venv venv
.\\venv\\Scripts\\activate

# 2. 安裝依賴與初始化 Seed 資料庫
pip install -r requirements.txt
python scripts/seed_db.py

# 3. 啟動 Uvicorn 服務
uvicorn src.main:app --host 0.0.0.0 --port 8005 --reload
