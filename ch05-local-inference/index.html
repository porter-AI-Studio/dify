地端推理引擎簡介

地端推理引擎允許開發者在本地環境中運行大型語言模型（LLM），提供更好的隱私保護和更快的回應速度。本章節將比較多種流行的地端推理引擎，包括 Ollama、vLLM、LiteLLM 和 NVIDIA NIM。

各推理引擎比較

推理引擎 Function Calling 支持 性能 易用性
Ollama 支持 高 簡單
vLLM 支持 非常高 中等
LiteLLM 支持 高 簡單
NVIDIA NIM 支持 非常高 複雜
💡

選擇地端推理引擎時，應根據具體需求權衡性能、易用性和 Function Calling 支持。

Windows Port Proxy 解決非對稱路由 (Connection Timeout)

在 Windows 上使用 Docker Desktop 運行 Dify，並嘗試連線至本機 (Host) 執行的 LiteLLM 或 vLLM 時，最常遇到的問題是 Connection Timeout。 這是因為 Dify 容器的 IP (如 172.x.x.x) 與 Windows 主機的區域網路 IP (如 192.168.0.x) 處於不同網段，導致了非對稱路由 (Asymmetric Routing) 的封包遺失。

為了徹底解決此問題，我們利用 Windows 內建的 netsh portproxy 將容器的請求進行 NAT 轉發。

PowerShell (Admin)
# 1. 將 18080 Port 轉發給本機 LiteLLM (4000)
PS> netsh interface portproxy add v4tov4 listenport=18080 listenaddress=0.0.0.0 connectport=4000 connectaddress=192.168.0.50

# 2. 確認轉發清單
PS> netsh interface portproxy show v4tov4

Listen on ipv4: Connect to ipv4:
Address Port Address Port
--------------- ---------- --------------- ----------
0.0.0.0 18080 192.168.0.50 4000
Dify Console - Provider Setup
API Endpoint URL
http://host.docker.internal:18080/litellm/v1
👉 Dify 容器透過 host.docker.internal 找到 Windows 主機的 18080 Port。

👉 Windows 主機再透過 Port Proxy 將封包做 NAT 轉換，發送給 LiteLLM (4000)。
⚠️

注意： 請務必將 connectaddress 填寫您 Windows 電腦的實際區網 IP (如 192.168.0.x)，切勿填寫 127.0.0.1，否則容器封包依然無法正確路由。

最佳實踐

  • 根據實際需求選擇合適的地端推理引擎。
  • 定期更新和維護所選擇的推理引擎。
  • 注意安全配置，特別是在使用 Port Proxy 時。
