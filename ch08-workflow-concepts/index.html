第 8 章 · Part 3：Workflow 設計

Pipeline 核心概念與節點類型

在 Dify 中，工作流（Workflow）的精髓在於 **Pipeline（管道）** 概念。本章將帶領讀者深入理解如何將複雜任務拆解為模組化節點，並藉由可視化資料流設計，建構出可控且高度擴展的 AI 應用。

一、什麼是 Pipeline (管道)？

在傳統的 AI 應用中，我們通常直接將使用者的提問丟給大語言模型（LLM），並期望模型一次就能吐出完美的答案。然而，在處理複雜的業務場景時，單次模型呼叫的可靠性極低。Dify 引入的 Pipeline 概念正是為了解決此痛點：

ℹ️
工作流的生產線哲學

Pipeline 就像是一條「工業生產線」，把一個複雜的 AI 任務拆解成多個明確的步驟（節點），並以「資料流（Data Flow）」的方式依序傳遞處理。每個節點只負責一項專一的工作，前一個節點的輸出即為下一個節點的輸入。

Dify 的 Pipeline 具備以下三大核心特徵：

  • 高度模組化（Modularization）：每個步驟都是獨立的節點，例如：文本解析節點、SQL 生成節點、API 請求節點、知識庫檢索節點等。節點之間彼此解耦，便於單獨進行優化或替換。
  • 嚴格的資料流（Data Flow）：節點與節點之間有清晰的變數傳遞。你可以明確定義 {{#node_name.output_var#}}，使資料流路徑百分之百可預期。
  • 可視化畫布設計（Visual Canvas）：Dify 提供了強大的可視化拖拽編輯介面，開發者能夠以連線的方式直接定義任務的執行拓撲，不再需要撰寫複雜的狀態機與鏈路控制程式碼。

二、與傳統單模型呼叫的差異

為了幫助讀者理解工作流的優勢，我們對傳統的單模型呼叫與 Pipeline 工作流進行了對比：

比較維度 單模型呼叫 (Single Model Call) Pipeline 工作流 (Workflow Pipeline)
系統結構 單次輸入 → 單次輸出 多步驟串接，可包含邏輯分支與循環
流程可控性 較低（全憑 LLM 的 Prompt 遵循能力） 高度可控（由系統工程邏輯嚴格限制執行鏈路）
擴展與維護 困難（Prompt 越加越長，極易產生副作用） 容易（可針對特定錯誤的節點進行替換與 debug）
異質系統整合 僅能透過 Tool Call（仰賴 LLM 自行判斷） 能直接編排硬編碼的 API、資料庫與自定義節點
適用場景 日常閒聊、簡單問答、單純文本重寫 複雜業務自動化、資料庫查詢（NL2SQL）、精確 RAG 檢索

三、常見的 Pipeline 應用場景與拓撲

在 Dify 中，最經典的 Pipeline 編排模式主要有以下兩種：

1. 資料庫查詢型 Pipeline (結合 NL2SQL)

在此模式下，Pipeline 負責將使用者的自然語言轉換為結構化的 SQL 語句，並調用資料庫工具取得結果後，再交由 LLM 轉譯回自然語言回覆給使用者。

2. 知識問答型 Pipeline (精確 RAG)

在知識問答（Retrieval-Augmented Generation）場景中，Pipeline 將問題進行向量化搜尋，從知識庫中取得相關片段（Context），並注入到 LLM 的 Prompt 中，以避免模型產生幻覺。

四、本章小結

Dify 的 Pipeline 概念讓我們能夠將 AI 從「玩具」提升為「工具」。當我們把 LLM 視為一個高度靈活但缺乏狀態保持的運算單元時，Pipeline 就是圍繞著它建構的硬編碼外骨骼（Hardcode Exoskeleton）。
