AWS 部署與 CI/CD

介紹 Dify 與 Login-App 的 AWS EC2 部署架構、自動化 CI/CD 部署腳本，以及 Dify 的全量備份與還原機制。

一、AWS 部署架構設計

在生產與 Demo 環境中，我們的 Dify 平台及 Login-App 被部署在同一台 AWS EC2 主機（主機別名：dify-aws-gyro，IP：54.250.195.137，作業系統為 Ubuntu）。

為了實現極速部署，Login-App 的 Docker 容器採用了 **掛載 Volume** 的模式：

  • 程式碼目錄 ~/Dify/login-app 掛載至容器的 /app。
  • 資料庫目錄 ~/Dify/login-app/data（內含 users.db）獨立掛載，與程式碼分離。

在這種架構下，**當我們修改程式碼時，不需要花費數分鐘重新 Build 新的 Docker Image**，只需要把最新代碼覆寫到 EC2 目錄下，然後重啟對應容器即可在 2 秒內完成熱部署。

二、自動化 CI/CD 部署腳本

我們編寫了 login-app/deploy-to-gyro.sh 部署腳本，在本地 Git Bash 中執行即可一鍵完成打包、上傳、解壓與重啟流程：

login-app/deploy-to-gyro.sh 
# deploy-to-gyro.sh
# 1. 打包（排除本地開發資料庫與快取）
tar \
  --exclude='login-app/data' \
  --exclude='login-app/__pycache__' \
  --exclude='login-app/.pytest_cache' \
  -czf /tmp/login-app-deploy.tar.gz login-app/

# 2. 上傳部署包至 AWS EC2
scp /tmp/login-app-deploy.tar.gz dify-aws-gyro:/tmp/

# 3. 遠端解壓並重啟對應 Docker 容器
ssh dify-aws-gyro "
  tar xzf /tmp/login-app-deploy.tar.gz -C ~/Dify/ &&
  docker restart docker-login_app-1 &&
  docker ps --format 'table {{.Names}}\t{{.Status}}' | grep login
"
⚠️
核心安全防禦：絕對不能覆蓋 data/ 資料夾

EC2 遠端主機的 data/users.db 儲存了線上所有真實用戶的帳號、密碼與對話對應關係。在執行打包時，tar 指令**必須使用 --exclude='login-app/data'**。解壓時也僅覆蓋代碼檔案，嚴禁覆寫資料庫檔案。

三、Dify 全量備份機制

Dify 平台儲存了大量的 Prompt、知識庫文件與歷史記錄，為了防範 AWS 主機意外損毀，我們必須落實每日的自動化備份。Dify 的備份必須覆蓋以下五大範圍：

  1. PostgreSQL 數據庫：儲存了所有的帳號、專案配置、Prompt 設計與知識庫 Metadata。
  2. Weaviate 向量庫：儲存了知識庫的分段向量索引。
  3. Storage 原始文件：儲存了用戶上傳的 PDF/TXT 等知識庫原始文檔與對話附件。
  4. Redis 快取：快取與 Celery 任務佇列狀態。
  5. .env 環境變數：包含所有的憑證、API 金鑰與資料庫密碼。

我們在 scripts/ 中提供了 PowerShell 備份腳本：

  • 本地 Docker 備份：backup-dify-local.ps1（保留 7 天）。
  • AWS EC2 備份：backup-dify-aws-gyro.ps1（保留 14 天）。腳本會自動建立 SSH 免密碼連線，備份成功後將包拉回本地備份目錄 backups/dify-aws-gyro/<timestamp>/ 下保存。

四、安全防禦的還原機制（Restore）

還原數據是高風險操作，會完全覆蓋目標環境的所有資料。為此，我們的還原腳本（restore-dify-local.ps1 與 restore-dify-aws-gyro.ps1）內建了**「還原前強制防禦備份」**機制：

  1. 在執行還原指令的當下，腳本會先自動將 EC2 上的現況進行全量打包備份。
  2. 跳出交互式確認（除非使用 -Force 參數）。
  3. 將備份包透過 SCP 上傳並解壓。
  4. 依序還原：.env $\rightarrow$ PostgreSQL $\rightarrow$ Weaviate $\rightarrow$ Storage $\rightarrow$ Redis。
  5. 自動重啟遠端 Dify 的 Docker Compose 服務，並清除 EC2 臨時目錄。

五、Windows 自動排程配置

為了實現無人值守的每日備份，我們可以在 Windows 主機中使用「工作排程器」設定自動排程：

Windows 工作排程器配置 
# Windows 工作排程器每日凌晨 03:00 自動備份 AWS Dify 環境的配置引數
# 啟動程式: powershell.exe
# 新增引數: -ExecutionPolicy Bypass -File C:\VSCode_Proj\Dify\scripts\backup-dify-aws-gyro.ps1
