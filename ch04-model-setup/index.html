新增 OpenAI 相容模型

逐步解說在 Dify 新增 openai_api_compatible 供應商時的必填三件事，以及常見的四大踩雷與解法。

本章節內容已更新，以下是新增 OpenAI 相容模型的詳細指南。

步驟一：了解 OpenAI 相容模型的必要條件

在 Dify 中新增 OpenAI 相容模型之前，您需要準備以下三項必要資訊：

  • API Base URL
  • API Key
  • 模型名稱
💡

確保您的 API Base URL 和 API Key 正確無誤，以避免後續的整合問題。

比較：舊方法 vs 新方法

項目 舊方法 新方法
API 設定 手動修改設定檔 透過 Dify UI 設定
模型新增 需要編輯程式碼 直接在介面新增

步驟二：設定 OpenAI 相容模型

請依照以下步驟，在 Dify 中新增 OpenAI 相容模型：

  1. 進入 Dify 的模型設定頁面
  2. 選擇「新增模型」並選取「OpenAI 相容」
  3. 填寫 API Base URL、API Key 和模型名稱
// 示例程式碼：設定 OpenAI 相容模型
const modelConfig = {
  apiBaseUrl: 'https://api.example.com/v1',
  apiKey: 'your_api_key_here',
  modelName: 'your_model_name'
};
⚠️

請注意，API Base URL 必須以 /v1 結尾，以符合 OpenAI API 的規範。

逐步程式碼解析

以下對設定 OpenAI 相容模型的程式碼進行詳細解析：

  • apiBaseUrl：指定模型的 API 基礎網址
  • apiKey：用於驗證的 API 金鑰
  • modelName：您要使用的模型名稱

常見問題與解決方案

在設定 OpenAI 相容模型時，您可能會遇到以下問題：

  • API 請求失敗
  • 模型無法載入
  • 驗證錯誤
  • 模型回應不正確

問題對照表：常見錯誤與解決方法

錯誤訊息 可能原因 解決方法
Invalid API Key API Key 不正確 檢查並更新 API Key
Model not found 模型名稱錯誤 確認模型名稱是否正確
ℹ️

如果您遇到其他問題，請參考 Dify 的官方文件或聯絡技術支援。

自訂模型的三大隱形地雷

在 Dify 透過 openai_api_compatible 新增模型時，有三個經常被忽略但會造成嚴重後果的設定：

1. Function Calling (Tool Call) 漏填

如果您使用的模型支援 Function Calling (例如 gpt-4o, llama-3.3, qwen-2.5)，您必須在「支援的功能」中打勾 Function calling。若漏勾此選項，Dify 會判定該模型不具備工具調用能力，進而在 Agent 模式時強制降級為舊式的 ReAct 策略，導致嚴重的效能與穩定度下降！

2. Context Size 設定錯誤

Context Size 決定了 Dify 傳遞歷史訊息與 RAG 檢索內容的長度上限。若填得太小，會導致知識庫檢索內容被截斷；若填得超過模型實際支援的長度，則會引發 API 報錯。請務必查閱模型提供商的文件準確填寫 (如 32768 或 128000)。

3. 供應商名稱字數限制

Dify 對於自訂供應商的名稱 (Provider Name) 有 30 個字元的硬性限制。若您填寫的名稱過長 (如 my-company-internal-llm-service-v1)，在儲存時會直接噴出驗證錯誤。建議使用簡短且具識別度的縮寫。

⚠️

注意： Dify 新版已鎖定新增流程，一旦模型儲存後，部分核心參數將無法事後修改，只能刪除重建。請在送出前再三確認上述三點設定無誤！

最佳實踐

為了確保 OpenAI 相容模型的穩定運作，請遵循以下最佳實踐：

  • 定期檢查 API Key 的有效性
  • 監控模型的回應時間和正確率
  • 保持 API Base URL 的更新
💡

建議您定期備份模型設定，以避免意外遺失。
