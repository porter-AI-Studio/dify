第 2 章 · Part 1：入門

本地 Docker 部署

從 git clone 到瀏覽器看到登入畫面——完整跑一遍，把每個步驟的「為什麼」說清楚

一、前置需求

開始之前，確認以下工具已安裝並可正常執行：

🐳
Docker Desktop ≥ 4.x
macOS / Windows / Linux 皆可。確認 docker compose（V2）可用，不是舊版 docker-compose
💾
磁碟空間 ≥ 10 GB
Images 約 4–5 GB，加上向量資料庫與上傳文件的持久化儲存
🧠
記憶體 ≥ 8 GB
Weaviate + PostgreSQL + Celery Workers 同時運行需要足夠 RAM
🌐
Port 80 未被占用
nginx 預設監聽 80。若已有其他服務占用，部署前需先修改 docker-compose.yaml

二、取得原始碼並設定環境變數

# 1. Clone 官方 repo
git clone https://github.com/langgenius/dify.git
cd dify/docker

# 2. 複製環境變數範本
cp .env.example .env

接著用文字編輯器打開 .env，至少修改以下三項才能安全運行：

環境變數
說明
SECRET_KEY
Flask session 加密金鑰。必須換成隨機字串，預設值不安全。 可用 openssl rand -base64 42 產生
DB_PASSWORD
PostgreSQL 密碼。預設值 difyai123456 不應用於對外服務
INIT_PASSWORD
第一次啟動時建立管理員帳號的初始密碼。設定後從瀏覽器完成初始化

三、啟動所有服務

# 在 dify/docker 目錄下執行
docker compose up -d

# 首次拉取 images 約需 3–10 分鐘（視網速）
# -d 表示背景執行

啟動完成後，開啟瀏覽器前往 http://localhost，若看到 Dify 初始化設定畫面即代表成功。

首次啟動較慢是正常的。後端會執行 Alembic 資料庫 migration， Celery Worker 等 migration 完成才會就緒。若看到 api 服務反覆重啟， 通常是資料庫還在初始化中，稍待幾十秒即可。

四、服務清單與 Port 對應

docker compose ps 會列出所有運行中的容器。以下是各服務的角色與 Port 規劃：

Docker Compose 服務一覽
服務名稱對外 Port說明
nginx 80, 443 反向代理，所有外部流量入口
web — Next.js 前端（Port 3000，僅 nginx 可見）
api — Flask 後端 API（Port 5001，僅 nginx 可見）
worker — Celery Worker，無對外 Port，消費 Redis 佇列
db 5432* PostgreSQL。*預設不對外暴露，開發時可在 compose 加入 ports
redis — Redis，Celery Broker + 快取，僅內部服務使用
weaviate — 預設向量資料庫，Port 8080 僅對 api/worker 開放
sandbox — Code Node 的隔離執行環境（gVisor），僅 api 可呼叫
ssrf_proxy — 防 SSRF 攻擊的 Squid Proxy，外部 HTTP 請求強制過此層

五、nginx 流量路徑

所有外部請求都從 Port 80 進入 nginx，再根據 URL 路徑分發：

外部請求 → http://localhost（Port 80）
↓
nginx 反向代理
路徑 / → web:3000（前端）
路徑 /api → api:5001（後端）
路徑 /v1 → api:5001（公開 API）
路徑 /console/api → api:5001（管理介面）

這個設計意味著從外部永遠只需接觸 nginx，不需要知道後端跑在哪個 Port。 如果你想在同一台機器上同時跑多個 Dify 實例，只需修改 nginx 的對外 Port（如 8080、8081）即可。

六、常用操作指令

# 所有指令都在 dify/docker 目錄下執行

# 查看所有服務狀態
docker compose ps

# 查看 api 服務的即時 log
docker compose logs -f api

# 查看多個服務的 log
docker compose logs -f api worker

# 重啟單一服務（不重建 image）
docker compose restart api

# 完全停止並移除容器（保留資料 volume）
docker compose down

# 完全清除，包含所有 volume（⚠️ 資料將遺失）
docker compose down -v
警告：docker compose down -v 會刪除所有持久化資料，包含 PostgreSQL 資料庫與向量資料庫的全部內容。 正式環境操作前請先備份，詳見第 3 章。

七、修改 Port 80 衝突

若本機已有其他服務（如 Apache、IIS）占用 Port 80，需修改 docker-compose.yaml 中 nginx 的對外 Port： 

# docker-compose.yaml（節錄）
services:
  nginx:
    ports:
      - "8080:80"   # 改為 8080 對外，nginx 內部仍是 80
      # - "80:80"   # 原本的設定，已注解掉

修改後執行 docker compose up -d --force-recreate nginx 讓新設定生效， 之後改用 http://localhost:8080 存取。

八、驗證部署成功

所有服務正常後，依序完成：

1
開啟 http://localhost，看到「設定管理員帳號」畫面
2
輸入 Email 與密碼完成初始化，自動跳轉至 Dashboard
3
前往「設定 → 模型供應商」，填入 API Key（如 OpenAI、Anthropic），測試連線成功
4
建立第一個 Chatbot 應用並在 Playground 送出一條訊息，確認模型有回應

下一章，我們進入版本升級與備份——讓你在不遺失任何資料的前提下，把 Dify 安全升級到最新版本。

九、Dify 網路架構與公網穿透 (Ngrok)

在地端部署 Dify 時，其網路架構由 docker-nginx-1 作為主要的反向代理 (Reverse Proxy) 處理所有外部請求，並轉發給內部的 api 容器。 如果您需要將本機的 Dify 提供給外部團隊測試，或對接 Webhook，最快的方式是使用 Ngrok 建立公網穿透隧道。

啟動 Ngrok 後，只需將提供的 https://xxxxx.ngrok.io URL 分享給團隊，他們就能存取您本地運行中的 Dify 環境。這在開發階段需要展示 Agent 成果或進行 Webhook 開發對接時非常實用！
